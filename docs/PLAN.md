# Plan and design

## Scope
Coding-interview review only (FAANG SDE2/SDE3/Staff coding rounds). System design, behavioral and
project deep-dives are out of scope for this repo. Java only, no external dependencies.

## Rule: templates always
No pattern, decision-tree entry or practice-map row exists without a Java template.
Each template file carries a header and a minimal paste-ready `CORE` block, with variants below it.

```java
// PATTERN:    Dijkstra
// RECOGNIZE:  weights >= 0, shortest path from one source
// COST:       O((V+E) log V)
// FOLLOW-UPS: path reconstruction, count paths, K-limited, 10x graph (bidirectional / A*)
// LC:         743, 1631, 787
```

## Target layout
```
coding-review/
├── Makefile               # test | site | check | review | log | new TOPIC=...
├── common/                # test harness: Check, Rand, Brute
├── topics/<topic>/        # topic.yaml, templates, tests/
├── drills/                # log.csv (date, lc_id, pattern, template, minutes, result, mistake), FORMATS.md
└── site/                  # build.py + template -> index.html (generated, never hand-edited)
```
- `topic.yaml`: intro, decision entries (`q`, `use`, `template`), SDE2/SDE3/Staff calibration, pattern -> LeetCode ids.
- `make check` fails if a decision entry has no template, a linked method is missing, a header is missing, or a template has no passing test.
- Tests: a known-input test per template (from a LeetCode example) plus seeded randomized cross-checks against brute force where applicable.
- Review loop: `make log` appends to `drills/log.csv`; `make review` lists problems due at 1/3/7/21 days and the template to re-read for each failure.

## Topic roadmap (coding only)
1. Graphs (done)
2. Dynamic programming: framework + linear/state-machine, knapsack, sequences, grid/interval, bitmask/digit/tree, DP + binary search/monotonic deque
3. Trees: binary tree, BST, trie, Fenwick/segment tree/sparse table
4. Arrays and hashing, sliding window and two pointers, monotonic stacks, heaps, intervals, binary search
5. Backtracking, greedy, linked lists, strings (KMP/Z/rolling hash/Manacher), bits and math, data-structure design (LRU/LFU, iterators)
6. Optional, Staff-only and low yield: DP optimizations (CHT, divide and conquer), sqrt decomposition

Weight DP by company: Meta reportedly tells interviewers not to ask pure DP; Google and Amazon do.

## Known gaps in graphs (templates owed)
- Minimax path via sorted edges + DSU (bottleneck variant)
- Evaluate division via DFS multiplying along the path


## Status update

(not yaml). The page is generated by `site/build.py`; `make check` enforces the template-first rule.
Out of scope by design: system design, behavioral, OOD and concurrency deep dives.
