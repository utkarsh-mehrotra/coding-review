# Quick-Revision Features Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the coding-review site faster for last-minute revision: a one-page cheat sheet, "use when" cues on every template, an essentials code view, a jump box, more accurate problem links with curated-list badges, a lighter page, and CI that keeps broken templates off the live site.

**Architecture:** Everything stays generated by `site/build.py` from `topics/*` and `tools/lc-coverage/data/*`, with no build tooling beyond Python stdlib and plain browser JS. A new `site/java_outline.py` gives one shared view of each Java file (members, line ranges, private helpers) that the anchors, folding and cues all use. Pure search logic lives in `site/assets/search.js` so node can test it; the coverage list moves to `site/coverage.json`, fetched on first use.

**Tech Stack:** Python 3.9+ stdlib (`unittest`), plain browser JS (ES5 style, like `app.js`), node 22 built-in test runner (`node --test`) for JS logic, Java 17+ (`javac`), GitHub Actions, Vercel.

**Spec:** Items 1-6 agreed in chat on 2026-11-17; the site is a quick-revision reference, not a practice tool (no progress tracking, scoring or drills). Summary:
1. Cheat sheet view: per topic, signal → approach → template, the pattern/complexity table, the pitfalls; printable.
2. "Use when" cues above every code card, from decision entries and `RECOGNIZE:` comments; `make check` reports members with no cue.
3. Essentials toggle that folds imports and private helpers; full code one click away.
4. Cmd+K / `/` jump box to any view, template member or problem; exact number match in the sidebar filter.
5. Fill templates with no problems (add `// LC nnn`, or mark "no LeetCode equivalent"); badges for LeetCode Top Interview 150 and LeetCode 75.
6. Load the coverage list only when its view opens; CI runs tests and checks on every push.

## Global Constraints

- No new dependencies: Python stdlib only, no JS libraries, no bundler. Python must run on 3.9 (local `python3` is 3.9.6): no `match`, no `X | Y` type syntax.
- `site/index.html`, `site/coverage.json` and `tools/lc-coverage/data/*.json` are generated and committed; never hand-edit them.
- LeetCode access: public GraphQL only, at most 1 request per second, user-agent `Mozilla/5.0`, no personal data, cached on disk.
- `make check` must keep failing on any broken `File#member` link (decisions, problems, cues).
- Every new view and control works in light, dark and auto themes using tokens in `site/assets/style.css`; no literal colors in component rules.
- Copy rules: plain, active voice; button labels say what happens ("Show essentials", "Show full code", "Print").
- Coverage totals must stay at 2,196 A+B problems unless Task 6 legitimately changes tiers; a problem shown under several templates counts once.

## Review Focus

1. **Copy while folded**: with essentials on, the Copy button must still copy the complete file, with no fold placeholders in it. (Task 2, `test_copy_text_excludes_fold_marks`.)
2. **Short problem numbers**: searching `70` or `1` must match problem 70 or 1 exactly, not 1070 or every number starting with 1; `70 climbing` must still work. (Task 5, `exact number` tests.)
3. **Opening the file directly** (`file://`, no fetch): the coverage view shows how to serve it locally; every other view still works. (Task 8, `test_coverage_view_has_offline_message`.)
4. **Deep link on first load**: opening `…/#coverage` directly must fetch and render, not only clicking the sidebar entry. (Task 8, `coverage loads on initial hash` node test.)
5. **Double counting**: a verified problem listed under two templates (e.g. LC 78 under `subsets` and `subsetsMask`) counts once in every total. (Task 6, `test_totals_count_each_problem_once`.)

### Task 5: Jump box and exact number search

**Files:** Create `site/assets/search.js`, `site/tests/search.test.js`; Modify `site/build.py` (inline `search.js`, build the jump index), `site/assets/app.js`, `site/assets/style.css`, `Makefile` (`test-site` also runs `node --test site/tests/`)

**Interfaces:**
- Produces `search.js` (UMD-lite: sets `window.CRSearch`, and `module.exports` when defined):

- Produces in the page: `<script type="application/json" id="jump-index">` built from the views, every decision template (`File#member`, sub = decision `q`) and every A/B problem (`"743 Network Delay Time"`, sub = template, anchor = `group_id`).
